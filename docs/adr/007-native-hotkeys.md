# ADR-007: Нативные Qt горячие клавиши

## Статус
Принято (2026-11)

## Контекст
Legacy Tkinter-GUI вручную биндил Ctrl+A/C/V/X/Z, включая поддержку
русской раскладки (`Cyrillic_ef` → Ctrl+A и т.д.). Но по факту
некоторые комбинации не работали (`bind_class("Entry", ...)` не
покрывал `ttk.Entry`), и пользователь жаловался на неудобство.

## Решение
Использовать **только нативные обработчики Qt**. `QLineEdit`,
`QPlainTextEdit`, `QTextEdit`, `QSpinBox` и т.д. нативно поддерживают
Ctrl+C/V/X/A/Z. Никаких кастомных `QShortcut` для системных действий.

## Обоснование
- Qt обрабатывает раскладки на уровне ОС
- Меньше кода, меньше багов
- Стандартное поведение, которое пользователь ожидает

## Последствия
- QA-чек-лист перед релизом:
  - `QLineEdit` (путь, расширения, ignore) — Ctrl+C/V/X/A/Z
  - `QPlainTextEdit` (редактор JSON, описания плана) — то же
  - `QSpinBox`/`QDoubleSpinBox` (настройки) — Ctrl+A/C/V
  - `QTextBrowser` (справка) — Ctrl+C
  - Диалоги (BomjAPI, настройки, результат) — **после** открытия
    (фокус на первом поле)
- Никаких `QShortcut(...)` для системных действий в коде
