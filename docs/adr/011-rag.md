# ADR-011: RAG для семантического отбора файлов

## Статус
Принято (2026-11)

## Контекст
`ContextOptimizer` (C0, до RAG) отбирал файлы через BFS-обход
графа импортов + PageRank + эвристику по цикломатической
сложности. Это работает для навигации по зависимостям, но
не отвечает на вопрос «какие файлы семантически релевантны
задаче», если имена не совпадают с описанием.

Пример: задача «добавить экспорт в CSV в модуль отчётов» —
BFS найдёт зависимости `reports.py`, но не файл `export_utils.py`,
если в графе импортов нет связи (экспорт подключается позже).

## Решение
Добавить **опциональный** RAG-слой:

1. **Chunking** (`core/rag/chunker.py`): AST-aware для Python —
   функции/классы как отдельные чанки, не разрываем тела функций
   посередине. Line-based 50/10 для не-Python.

2. **Embeddings** (`core/rag/embeddings.py`): два бэкенда за одним
   Protocol.
   - `OllamaEmbeddings` → `/api/embed`, модель `nomic-embed-text`
     (768d). Zero dependencies, если Ollama стоит (а она уже
     поддерживается для LLM).
   - `SentenceTransformersEmbeddings` → `all-MiniLM-L6-v2` (384d),
     `pyproject [rag]` extra. ~500 MB torch.
   - Factory `auto`: Ollama, если доступна, иначе ST, иначе
     `RuntimeError` с инструкцией.

3. **Vector store** (`core/rag/store.py`): `sqlite-vec` в
   `.pig/rag.db`. Один файл, KNN через `vec0` virtual table.
   Dimension фиксируется в meta-таблице; смена бэкенда →
   `DimensionMismatchError`.

4. **Hybrid retriever** (`core/rag/retriever.py`): BM25 +
   vector + RRF fusion (k=60). BM25 ловит имена функций,
   dense — семантику. RRF не требует нормализации скоров.
   `RobustBM25` — `BM25Okapi` с idf-клэмпом `[0.1, ∞)`, чтобы
   работало на корпусах из 1–2 файлов.

5. **Indexer + Optimizer** (`core/rag/indexer.py`,
   `core/rag/optimizer.py`): `RagOptimizer.optimize()` — drop-in
   для `ContextOptimizer.optimize()`. Первый запуск строит
   `.pig/rag.db`, дальше переиспользует.

6. **UI** (`optimize_dialog.py`, `optimize_worker.py`): чекбокс
   «Использовать RAG». **Выключен по умолчанию** — RAG требует
   Ollama или ST. При отсутствии бэкенда — молчаливый fallback
   на `ContextOptimizer` с предупреждением в статус-баре.

## Обоснование

**Почему opt-in, а не default:**
- RAG требует либо Ollama (не у всех), либо 500 MB ST.
- Первая индексация проекта 5k файлов — 1-2 минуты (эмбеддинги).
- Старый путь быстрый и работает везде.

**Почему sqlite-vec, а не chromadb/faiss:**
- chromadb → duckdb (~100 MB) + client/server split.
- faiss → in-memory, нет персистентности.
- sqlite-vec → native extension в stdlib sqlite3, ~100 KB,
  один файл `.pig/rag.db`.

**Почему RRF, а не weighted sum:**
- BM25 scores и cosine distances несоизмеримы по магнитуде.
- RRF использует rank order — нулевая настройка, стандарт
  (Cormack 2009).

**Почему AST, а не tree-sitter:**
- Python `ast` встроен, покрывает наш основной язык, 0 новых
  deps.
- tree-sitter + tree-sitter-python = ~5 MB native binary.
- cAST paper подтверждает: line-based ломает функции — AST
  минимум полезного.

## Последствия

- `.pig/rag.db` в `.gitignore` (per-project, ~10 MB на 10k
  чанков).
- Coverage floor остаётся 67% — RAG-модули покрыты ~80%.
- Frozen `.exe`: `sqlite-vec` + `rank-bm25` добавляют ~500 KB
  к размеру. `sentence-transformers` **не** включён в сборку
  (extra), Ollama-path работает без него.
- Инкрементальная индексация не реализована: при `build()`
  индекс полностью пересобирается. Future work — mtime-трекинг
  + add/delete по файлам.
