## Первый запуск

### Из исходников

```bash
git clone <ваш-форк> pig-t3-fork
cd pig-t3-fork
uv sync --extra dev
uv run python -m PIG_T3
```

### Готовый бинарник

- Linux: `./dist/PIG-T3`
- Windows: `dist\PIG-T3.exe` (SmartScreen → More info → Run anyway)

При первом запуске:

1. Откроется окно с тёмной темой Qt-Material.
2. Пять вкладок: **Генератор**, **Инфо**, **Редактор**, **План**,
   **Анализ кода**.
3. Справа-сверху кнопка ⚙️ — настройки.
4. Внизу статус-бар: текущий статус + версия.

### Быстрая проверка

- **Генератор** → «Авто» (путь станет корнем репо) →
  «ГЕНЕРИРОВАТЬ КОНТЕКСТ» → через 2–5 секунд появится
  `project_context.txt`.
- **Анализ кода** → путь уже стоит → «ЗАПУСТИТЬ АНАЛИЗ» → таблица
  с метриками.

Если что-то не работает — см. [Troubleshooting](#troubleshooting).

## Сценарий 1: исправить одну функцию

**Задача:** в проекте `~/myapp/` есть функция `calculate_total` в
`billing.py`, она падает на пустой корзине. Нужно добавить проверку.

### Шаг 1. Сгенерировать контекст

1. Вкладка **Генератор**.
2. «Папка проекта» → выберите `~/myapp/` (или «Обзор…»).
3. «Расширения» → оставьте `.py` или добавьте `.json, .yml`.
4. «Исключить (Ignore)» → `venv, __pycache__, .git` (по умолчанию).
5. Опции:
   - ✅ **Нумеровать строки** — обязательно, если хотите
     `replace_lines`.
   - ✅ **Добавить инструкцию для AI (JSON Format)** — LLM узнает,
     как правильно оформить ответ.
6. Справа дерево — снимите галочки с файлов, которые **не нужны**
   (например, `tests/`, `docs/`). Папку можно снять целиком.
7. Нажмите **«ГЕНЕРИРОВАТЬ КОНТЕКСТ»**.
8. По завершении появится диалог «Успех» с путём
   `~/myapp/project_context.txt`.

### Шаг 2. Отправить в AI

1. Откройте `project_context.txt` (или возьмите из буфера, если
   включили «Авто-копировать ФАЙЛ в буфер» — работает только на
   Windows; на Linux скопируйте вручную).
2. Загрузите файл в ChatGPT / Claude / DeepSeek.
3. Промпт:

   ```text
   В проекте выше функция calculate_total падает на пустой корзине
   с IndexError. Добавь проверку: если корзина пустая, вернуть 0.
   Верни JSON по инструкции из конца файла.
   ```

### Шаг 3. Применить ответ

AI вернёт JSON:

```json
[
  {
    "action": "edit",
    "path": "billing.py",
    "explanation": "Handle empty cart",
    "operations": [
      {
        "type": "insert_after_line",
        "line": 42,
        "content": "    if not cart:\n        return 0\n"
      }
    ]
  }
]
```

1. Вкладка **Редактор**.
2. Скопируйте JSON → **Вставить** (или `Ctrl+V`).
3. **Проверить / Форматировать** — увидите
   `✅ Валидный JSON. Операций: 1`.
4. **ПРИМЕНИТЬ ИЗМЕНЕНИЯ** — откроется окно с логом:

   ```text
   ➕ Insert billing.py: после строки 42
      💡 Пояснение: Handle empty cart
   ```

### Шаг 4. Проверить и отменить при необходимости

1. Откройте `billing.py` в редакторе кода — увидите добавленные
   строки.
2. Если что-то не так — **Отменить** в Редакторе. Файл вернётся к
   бэкапу `.pig/backups/<uuid>/before/`.
3. **Повторить** — применит заново.

Бэкапы хранятся в `~/myapp/.pig/backups/` (максимум 10 последних).

## Сценарий 2: переделать проект

**Задача:** есть MVP на Python (одна папка, 5 файлов), нужно
превратить в структурированный пакет с тестами, CLI и документацией.

### Шаг 1. Описать цель

Вкладка **План** → **Новый План** → введите:

```text
Превратить плоскую папку проекта в пакет myapp/ с модулями:
- cli.py (click или argparse)
- core.py (бизнес-логика)
- storage.py (SQLite)
- tests/ (pytest, ≥3 теста на модуль)
- README.md
Порядок: setup → core → storage → cli → tests → docs.
```

Выберите модель LLM (Ollama локально, Web через Playwright или
BomjAPI для ручного ввода) → **Создать план**.

Через 30–120 секунд появится список шагов в левой панели.

### Шаг 2. Просмотреть план

Каждый шаг кликабелен. Справа — название, описание, отчёт. Кнопка
«Удалить шаг» удаляет, чекбокс «Шаг выполнен» отмечает.

Если план плохой — **Новый План** заново с уточнённым описанием.

### Шаг 3. Выполнить

**Вариант A — шаг за шагом (рекомендуется для контроля):**

1. Выберите шаг → **ВЫПОЛНИТЬ ВЫБРАННЫЙ ШАГ**.
2. Приложение:
   - собирает контекст (все `.py` из проекта)
   - отправляет промпт + план в LLM
   - получает JSON-патч
   - применяет, обновляет статус шага
3. Повторите для следующего шага.

**Вариант B — весь план сразу:**

1. Модель должна быть выбрана.
2. **ВЫПОЛНИТЬ ВЕСЬ ПЛАН**.
3. Прогресс-бар `X / N шагов` внизу.
4. Остановка: **ОСТАНОВИТЬ ПОЛНЫЙ ПЛАН** (текущий шаг завершится,
   следующий не начнётся).

**Авто-применение** (галочка внизу) — по умолчанию **выключено**.
Тогда LLM-ответ попадает в **Редактор**, и вы проверяете перед
применением. Включите, если доверяете модели.

### Шаг 4. Ретрай при ошибках

Если шаг упал (`status=failed`):

1. Выберите упавший шаг (подсвечен красным).
2. **Повторить шаг с ошибкой** — тот же шаг выполнится заново.
3. При повторной ошибке — откройте **Отчёт ИИ** справа, посмотрите
   сообщение, уточните описание шага, попробуйте снова.

### Шаг 5. Git (опционально)

В **Настройки → Функционал → Git**:

- ✅ «Включить авто-коммиты» — перед каждым шагом создаётся ветка
  `pig_plan_<timestamp>` и коммит «auto-save before plan execution».
- ✅ «Push после каждого шага» — если хотите синхронизировать на
  remote (осторожно: шумные коммиты).

Откат: `git checkout master` — все коммиты плана остаются в ветке
`pig_plan_*`.

## Сценарий 3: анализ качества кода

Вкладка **Анализ кода**.

1. «Целевая папка» уже заполнена путём из Генератора. Если нет —
   введите вручную.
2. **ЗАПУСТИТЬ АНАЛИЗ**.
3. При первом запуске приложение установит `radon`, `pylint`,
   `bandit`, `vulture` через `pip` (нужен интернет, ~30 сек).
4. Через 10–120 секунд (зависит от размера проекта) появится
   таблица.

### Что означают колонки

| Колонка | Что это | Хорошо | Плохо |
| :--- | :--- | :--- | :--- |
| Строк | SLOC (без пустых/комментариев) | — | — |
| Сложность | Cyclomatic Complexity (Radon) | 1–10 | 21+ |
| Поддерж. | Maintainability Index (Radon) | > 20 | < 10 |
| Score | Pylint score | > 8 | < 5 |
| Безоп. | Bandit security issues | 0 | ≥ 2 |

Цвет ячейки: зелёный / жёлтый / красный по порогам выше.

### Просмотр деталей

Клик по строке → внизу панель со списком issues:

```text
📄 billing.py

Cyclomatic Complex.:   12.5 ⚠️
Maintainability I.:    22.0 🟢
Linter Score:           7.2 ⚠️
Security Issues:        0 ✅

🔍 Найдено 5 проблем:
01. [WARN]  строка 42  [PYLINT]  W0611: unused-import
02. [CRIT]  строка 87  [PYLINT]  E0001: syntax-error
...
```

### Сортировка и компактный режим

- Клик по заголовку колонки — сортировка.
- **«Свёрнутый вид»** — оставляет только `path` + сортируемую
  метрику. Удобно, когда нужен только «худший по сложности» список.

### Когда использовать

- Перед рефакторингом — найдите проблемные файлы.
- После AI-патчей — проверьте, не наломал ли LLM.
- В CI — вынесите `radon cc`/`pylint` отдельно, здесь это UI.

## Сценарий 4: оптимизация контекста

**Задача:** проект 500+ файлов, весь контекст не влезает в окно
LLM. Нужно выбрать 20 самых важных файлов для задачи.

Вкладка **Генератор** → **Оптимизация контекста**.

### Диалог

1. **Описание задачи** — «добавить экспорт в CSV в модуль отчётов».
2. **Процент сжатия** — сколько % объёма оставить (например, 20%).
   Под слайдером — «Ожидаемо токенов: ~5000 (из ~25000)».
3. **Глубина BFS** — 2 по умолчанию. Больше — шире обход графа
   импортов (медленнее, но точнее).
4. **Модель LLM:**
   - `None` — офлайн, только BFS + PageRank + complexity-эвристика.
     Быстро, бесплатно, работает без интернета.
   - `BomjAPI` — откроется окно ручного ввода: скопируйте промпт из
     левой части, вставьте в ChatGPT/Claude, скопируйте ответ в
     правую, нажмите «ACCEPT».
   - `Web: DeepSeek` / `Web: Gemini` — Playwright автоматически
     откроет браузер, отправит промпт, подождёт ответ, закроет.
   - `Ollama-модели` (например, `qwen2.5-coder`) — локально, если
     Ollama запущена.
5. **НАЧАТЬ ОПТИМИЗАЦИЮ**.

### Что происходит

- Офлайн (или LLM-ранжирование) отбирает N файлов с наибольшим
  комбинированным весом (LLM 60% + PageRank 30% + complexity 10%).
- В дереве Генератора **остаются отмеченными только выбранные**
  файлы, остальные — пустые чекбоксы.


### Режим RAG (семантический поиск)

Галочка **«Использовать RAG»** в диалоге оптимизации включает
семантический поиск по коду:

- **Первый запуск:** индексирует проект в `.pig/rag.db`.
  Прогресс в статусе: «Индексация: 120/450 чанков». Время: 1–2 мин
  на 5k файлов (Ollama) или 3–5 мин (sentence-transformers).
- **Повторные запуски:** индекс переиспользуется. Только изменившиеся
  файлы не переиндексируются (полная пересборка пока — future work).
- **Требуется:** Ollama с моделью `nomic-embed-text` **или**
  `uv sync --extra rag`. Без них — молчаливый fallback на старую
  эвристику.

**Что даёт:** для задачи «добавить экспорт в CSV в модуль отчётов»
RAG найдёт `export_utils.py`, даже если он не в графе импортов
`reports.py`. BFS+PageRank такое не находит.

**Когда выключить:** если проект огромный (индексация долгая), или
Ollama не запущена, или задача тривиальная — старая эвристика
быстрее и не хуже.

### Дальше

Обычный путь: **ГЕНЕРИРОВАТЬ КОНТЕКСТ** — теперь отчёт будет
содержать только выбранные файлы.

## Настройка LLM

### Ollama (локально, бесплатно)

1. Установите: [ollama.com](https://ollama.com).
2. Запустите: `ollama serve` (если не работает как служба).
3. Скачайте модель:

   ```bash
   ollama pull qwen2.5-coder:7b
   ```

4. Перезапустите PIG-T3. В **Редактор → Модель** и
   **План → Модель** появятся ваши модели. Список кэшируется на
   60 секунд.

### LM Studio (локально, альтернатива Ollama)

1. Установите: [lmstudio.ai](https://lmstudio.ai).
2. Скачайте модель в приложении (например, `Qwen2.5-Coder-7B-Instruct`).
3. Вкладка **Local Server** → **Start Server** (по умолчанию `localhost:1234`).
4. В PIG-T3 модели автоматически появятся в списках Модель
   (Редактор / Оптимизация / План) с префиксом **`LM Studio: `**.
5. **Настройки → Функционал → «LM Studio (OpenAI-совместимый)»**
   — при необходимости измените:
   - Base URL (`http://localhost:1234/v1` по умолчанию)
   - API key (LM Studio не требует, но некоторые reverse-proxy
     конфигурации могут)
   - Таймаут (600 сек по умолчанию)
   - Embeddings модель (пусто = автоопределение — первая из
     `/v1/models`)

**Плюсы:** удобный GUI для управления моделями; OpenAI-совместимый
API (можно потом переехать на vLLM / Together без изменений в коде).

**Минусы:** embeddings-модели поддерживаются не во всех версиях
LM Studio — если `/v1/embeddings` недоступен, RAG упадёт в fallback
на Ollama или sentence-transformers.

### Web API (DeepSeek / Gemini)

1. Установите Chromium для Playwright:

   ```bash
   uv run playwright install chromium
   ```

2. В **Редактор → Модель** выберите `Web: DeepSeek` (или Gemini).
3. Первый запрос откроет браузер, попросит залогиниться в чат
   (один раз). Cookies сохраняются в профиле `./profiles/`.
4. Модель — обычная веб-версия, таймаут 600 сек по умолчанию
   (настраивается в **Настройки → LLM**).

**Плюсы:** бесплатно, без API-ключей, работает с подпиской.
**Минусы:** медленно, зависит от вёрстки чата (может сломаться при
обновлении интерфейса DeepSeek/Gemini).

### BomjAPI (ручной ввод)

Для случаев, когда нет ни локальной Ollama, ни желания настраивать
Playwright, но есть ChatGPT/Claude в браузере:

1. **Редактор → Модель → BomjAPI**.
2. При auto-fix / оптимизации / выполнении шага плана откроется
   диалог «Request to BomjAPI»:
   - Слева — промпт (read-only). **COPY** — в буфер.
   - Справа — большое поле для ответа. **PASTE** — из буфера.
   - **CHECK** — валидация (если для модели задан валидатор).
   - **ACCEPT** — принять и вернуться в приложение.
3. Скопируйте промпт → вставьте в ChatGPT → ответ скопируйте →
   вставьте в правую панель → ACCEPT.

## Troubleshooting

### `free(): invalid size` при выходе

Историческая проблема (T-107), исправлена на 5 уровнях. Если
вернулась:

1. Запустите с `PIG_NO_SPLASH=1 ./run.sh`.
2. Проверьте `/tmp/pig_crash.log` (Linux) или
   `%TEMP%\pig_crash.log` (Windows) — там Python-стек.

### `Gtk-Message: Failed to load module "xapp-gtk3-module"`

Безвредное предупреждение GTK (Linux Mint / XApps). Игнорируйте или
установите `libxapp-gtk3-module`.

### Ollama не появляется в списке моделей

1. `ollama serve` запущен?
2. `curl http://localhost:11434/api/tags` — работает?
3. Список кэшируется на 60 сек. Перезапуск диалога не обновит
   сразу — подождите минуту.
4. Логи: если запускать `./run.sh` из терминала, там будут
   `Optimization LLM Error: ...`.

### DeepSeek / Gemini отваливается с таймаутом

1. Откройте **Настройки → LLM** → увеличьте «Таймаут Web API» до
   1200 сек.
2. Убедитесь, что в браузере вы залогинены (первый запуск —
   интерактивный).
3. Вёрстка чата могла измениться — обновите форк (issue/PR
   welcome).

### Ctrl+C / Ctrl+V не работают

Не должно. Если воспроизводится — укажите виджет и ОС, создайте
issue. QA-чек-лист покрывает `QLineEdit`, `QPlainTextEdit`,
`QSpinBox`, `QTextBrowser`, все диалоги.

### Тема выглядит неправильно после обновления

`pink` / `eye_care` → `light`, `dark_pink` → `dark` при загрузке
конфига (ADR-002). Вернуть кастомную тему нельзя — Qt-Material
поддерживает только базовые + цветовые акценты. Редактируйте
`gui_qt/theme.py:_QT_MATERIAL` (`dark_teal.xml`, `dark_blue.xml` и
т.д.).

### PyInstaller-бинарник: `attempted relative import`

Собирайте **только** `pyinstaller pig_t3.spec --noconfirm`. Entry
point — `run.py`, не `PIG_T3/main.py` (там относительные импорты,
которые ломаются в frozen-режиме).

## Сценарий 5: AI сам пишет и тестирует

**Задача:** дать AI написать тест и сразу прогнать его — не
переключаясь в терминал.

### Включение

**⚙️ Настройки → Функционал → «Выполнение команд»:**
- ✅ Разрешить выполнение команд из JSON-патча
- ✅ Подтверждать команды в редакторе (рекомендуется)
- Таймаут: 120 сек
- Whitelist: `pytest,ruff,mypy,git` (опционально)

### Prompt для AI

```
Создай tests/test_calculate.py с 3 тестами для функции calculate_total
из billing.py. Потом запусти pytest tests/test_calculate.py -v.
Если упадёт — исправь и перезапусти. on_failure: abort.
Формат: JSON по инструкции.
```

### Что вернёт AI

```json
[
  {"action": "create", "path": "tests/test_calculate.py", "content": "..."},
  {
    "action": "run_command",
    "command": "pytest tests/test_calculate.py -v",
    "output_path": ".pig/cmd/pytest_calc.log",
    "timeout_sec": 120,
    "on_failure": "abort",
    "explanation": "Verify the new tests pass"
  }
]
```

### Что увидите

**«Просмотр изменений»:**
```
➕  tests/test_calculate.py
▶  $ pytest tests/test_calculate.py -v
```

Клик на команду — детали: `timeout: 120`, `output_path`,
`on_failure: abort`.

**«Применить»:**
- Создаётся `tests/test_calculate.py`
- Запускается `pytest`. Вывод в `.pig/cmd/pytest_calc.log`
- Если тесты прошли → `✅ RUN: pytest … (exit=0)`
- Если упали → `❌ RUN: … (exit=1)` + `⏹ PIPELINE ABORTED`,
  файлы уже созданы (undo доступен)

### В плане (авто)

В шаге плана `run_command` работает без диалога (только opt-in в
настройках). Если команда упала и `on_failure: abort` — шаг
переходит в `failed`, весь план останавливается. Кнопка
«Повторить шаг с ошибкой» — стандартная.

## FAQ

**Где хранятся настройки?**
`app_config.json` рядом с бинарником (или корнем репо) +
`.pig/state.json` в папке каждого проекта.

**Куда сохраняются бэкапы?**
`<project>/.pig/backups/<uuid>/{before,after}/`. Лимит 10 последних —
старые удаляются автоматически.

**Можно ли отменить AI-правку?**
Да — вкладка **Редактор** → **Отменить**. Восстанавливает `before/`.

**Как работает `line_numbers` + `replace_lines`?**
Контекст содержит номера строк (`   42 | def f():`). AI возвращает
`{"type": "replace_lines", "start": 42, "end": 45, "content": "..."}`.
Патчер заменяет строки 42–45 на новый контент. **Не включайте**
неизменные соседние строки в `content` — они задублируются (есть
anti-dup защита, но лучше не полагаться).

**Почему AI иногда возвращает «невалидный JSON»?**
Ошибка модели. **Редактор → Проверить** → ошибка → если выбрана
модель → **Auto-Fix** (Ollama / Web / BomjAPI перезапишет JSON).

**Работает ли проект без интернета?**
Да, если: (а) LLM = `None` (офлайн-эвристика) или Ollama локально,
и (б) не нужен Web API. Генератор, Редактор (без Auto-Fix), Анализ
кода, План с локальной моделью — всё работает офлайн.

**Как обновиться до свежей версии?**

```bash
git pull
uv sync
```

Конфиг и `.pig/state.json` совместимы (ADR-006), темы мигрируют
автоматически.
